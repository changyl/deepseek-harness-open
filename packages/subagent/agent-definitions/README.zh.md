# @deepseek-ai/dsh-agent-definitions

[English](README.md) | 中文

## 概述

使用本包可为一次组合提供一份统一的专用子 agent 定义目录，定义可来自项目文件、插件或远程服务。它合并每个提供方的定义，以可预期的方式解析重名，校验每个候选项，并按需加载胜出定义的 persona 与收窄字段。当定义需要来自多个来源，或来源不是本地文件系统时挂载它；若需要文件编写的定义与模型访问，请搭配 `dsh-agent-definitions-filesystem` 与 `dsh-tool-subagent`，因为本包自身不提供任何定义。

<a id="use-this-package"></a>
## 使用本包

挂载该插件即可为一次组合提供一个 agent 定义注册表。定义来源（提供方）与消费方（面向模型的委派工具，或你自己的代码）都通过 `ctx.agentDefinitions` 访问它；一次查找会合并各提供方针对当前工作区与查看作用域报告的成果。

### 何时选择

当专用子 agent 定义需要经由一个接口来自多个来源，或来源不是本地文件系统时，使用 `dsh-agent-definitions`。当没有任何组合需要专用子 agent 时请避免使用：该插件会引入一个服务与逐次查找的发现成本。随仓库提供的本地提供方（`dsh-agent-definitions-filesystem`）与面向模型的消费方（`dsh-tool-subagent`）是独立的包；当部署需要文件编写的定义与模型访问时，请一并挂载它们。

### 挂载与配置

该插件是一个 Cordis 服务，不接受任何配置；注册提供方无需该服务之外的任何东西。

```yaml
- name: '@deepseek-ai/dsh-agent-definitions'
```

### 注册表提供的能力

- **一份合并目录。** 消费方查询当前工作区与查看作用域可见的定义，即可获得全部胜出摘要并按名称排序，无需自行处理提供方特有的顺序或去重。
- **按需获取完整定义。** `get(name, options)` 返回包含 persona 正文的胜出定义，并在返回前重新校验提供方的响应。
- **完整或部分观测。** `snapshot(options)` 在返回摘要的同时返回 `complete` 标志；只要任一提供方报告其来源列举不完整，该标志即为 `false`，消费方因此可以保留最后一份可用状态，而不会把一次瞬时失败呈现为删除。
- **提供方注册。** 提供方插件在其 `apply()` 期间通过 `registerProvider(create)` 同步注册到调用方 context 的作用域层；该调用返回用于注销的 Cordis effect disposer，同一层内重名的提供方会抛出错误。
- **变更通知。** 提供方可在该次注册仍然有效时调用其注册作用域内的 `invalidate()`；随后注册表发出 `agent-definitions/change`，这是一条不过滤的通知，监听器按各自的查找选项重新获取。

注册会归入其调用 context 所属作用域的层：宿主行与仓库插件进入全局层，而由 agent preset 常驻组合挂载的插件进入该 preset 的层。一次读取会合并全局层与查看作用域链，重名时最近的一层直接胜出。

| 同一层内的重名 | 决定依据 |
|---|---|
| 首先 | 数值最小的 `rank` |
| 其次 | 提供方注册顺序 |
| 再次 | 提供方自身的列举顺序 |
| 记录 | 之后每个重复项都被忽略，并给出标明其来源的警告 |

### 校验规则

提供方的 `list()` 必须返回候选项数组，或 `{ definitions, complete }` 观测对象。每个候选项在被采纳前都会经过校验：

- `name` 匹配 `^[a-z0-9]+(?:-[a-z0-9]+)*$`。
- `description`、`provider` 与 `source` 为非空字符串。
- `rank` 为整数。
- `tools` 存在时必须是非空的非空工具名数组。
- `model` 与 `reasoningEffort` 存在时必须为非空字符串，`maxDepth` 存在时必须为非负整数。
- 已加载的定义会重复上述字段并额外要求非空 `instructions`，且其 `name` 必须仍等于同一次读取中选中的候选项名称。

定义只能收窄子 agent。`tools` 以所列白名单替换子 agent 继承的工具集，省略的字段则继承子 agent 原本会得到的值，因此任何定义都无法授予发起委派的 agent 本身不具备的工具。

### 可观察的成功与失败

任一提供方报告的定义都会出现在合并目录中，以确切 kebab-case 名称调用 `get()` 会返回完整定义；无效或未知名称返回 `undefined`，而不是抛出错误。`list()` 抛错的提供方会被记录并跳过，该次读取的观测随之变为不完整；显式的不完整观测仍会贡献它确实返回的候选项。格式错误的候选项或观测会让该次读取失败，而不会被静默跳过。每次提供方注册、dispose 与 `invalidate()` 都会发出 `agent-definitions/change`；抛出或拒绝的监听器会被记录，且不影响注册表自身的变更。

## 理解实现

<details>
<summary>实现细节——点击展开</summary>

本节解释注册表如何收集、合并与加载提供方目录；可观察行为已在[使用本包](#use-this-package)中完整说明。

### 设计理念

本包建立在一项职责分离之上：注册表负责层合并、重名解析与校验，提供方负责定义从何而来。提供方是一个借用的同进程对象，其 `list()` 返回候选项，`get()` 加载一份完整定义；除校验字段外，注册表从不检查定义内容。

注册通过 `@deepseek-ai/dsh-scope` 按作用域分层，沿用工具注册表确立的安排。每一层保有自己的提供方表，一次读取先走全局层，再沿查看作用域链从最远祖先走到确切作用域。

### 源码地图

| 文件 | 职责 |
|---|---|
| [`src/index.ts`](src/index.ts) | 服务类、提供方注册、分层收集、候选项与定义校验、变更通知 |
| — | 不发布运行时不变式伴生入口；注册表在消费该观测的那次读取内部校验每份提供方观测，因此不存在可供交叉核对的第二份冲突观测。 |

### 目录收集

在每一层内，提供方被逐个等待；某次拒绝会被记录、将该次读取标记为不完整，并继续处理下一个提供方。候选项经过校验、排序、在该层内以先到者胜出去重，然后写入合并映射，同名时较近的一层会替换较远的一层。摘要会丢弃提供方自有的 locator 与 rank，并按名称码点排序。

### 加载与陈旧性

`get()` 在任何提供方工作之前就拒绝不符合 kebab-case 语法的名称，重新收集目录，并把胜出候选项的不透明 locator 传回其所属提供方。定义从不缓存：每次加载都向提供方索取当前正文，且当定义的 `name` 不再等于所选候选项时返回 `undefined`，而不是返回不匹配的正文。

### 取消与失效

`options.signal` 在收集前、每次等待提供方前后以及收集后都会被检查；中止会以 signal 的原因拒绝该次读取，而提供方在中止后抛出错误时会传播该中止，而不是被跳过。提供方被 dispose 时会中止注册作用域内的生命周期 signal 并发出变更事件。监听器失败会被记录警告并加以隔离，因此任何观察者都无法否决注册表自身的变更。

</details>

<a id="model-experience"></a>
## 模型体验

通过 `dsh-tool-subagent` 间接影响模型；它把胜出的定义摘要渲染成一条持久化的 available-subagents 目录消息，并把所选定义的 persona 与收窄字段应用到它启动的子 agent 上。

#### KV Cache 影响

无直接提示词影响。上述消费方拥有那条持久化目录消息：渲染结果不变时不发布任何内容，渲染结果变化时会在既有请求前缀之后追加一条替换消息。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>


这些限制说明注册表何时不合适，或何时需要特别的运维注意。它们是当前包约束，不是任务积压。

- **不支持运行时注册单个定义**——定义只能经由已注册的提供方存在，因此一次性的内存定义需要由某个提供方来承载，而不能直接调用注册表。
- **每次读取都会重新列举每个提供方**——注册表不保留缓存，也不提供监视或 TTL，因此每次读取都要付出每个提供方的发现成本，可变的提供方必须先调用 `invalidate()`，消费方才能察觉变化。
- **定义只能收窄子 agent**——`tools`、`model`、`reasoningEffort` 与 `maxDepth` 限制子 agent 原本会继承的组合；没有任何字段会授予发起委派的 agent 本身不具备的能力。
- **所选定义的名称不被持久化**——只有其解析后的效果会到达子 agent，因此之后注册表的变化只影响新的委派，也无法把结果追溯回早先会话所用的定义。
