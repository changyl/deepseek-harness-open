# Agent Note: 在右侧 Sidebar 中编辑文本文档

Status: implemented

[English](2026-09-15-sidebar-document-editing.md) | 中文

## Problem

右侧 Sidebar 只能预览文件，不能修改它们。Agent 刚写好的 Markdown 文件——或者读者希望 Agent 据此工作的文件——可以阅读、搜索，也可以与某一轮的改动做对比，但哪怕最小的修正都意味着离开产品去用外部编辑器，再回来。预览自带的改动评审可以回滚整轮改动；没有任何东西可以编辑一行。

预览还以一种特定的方式并不适合编辑，而这必须在做任何事之前先解决。它的内容以行的分页形式到达，而一页是有损视图：`cutPage` 把保留下来的行重新拼接，因此以换行结尾的文件与不以换行结尾的文件会产生完全相同的文本。任何以分页作为初值的编辑器都会在写回时悄悄丢掉文件末尾的换行——这是首次保存即发生的数据丢失，而且正发生在本功能存在意义所在的流程里。

## Decision

`text` tab 类型现在带有编辑会话，文件服务也新增了支撑它的唯一一个变更操作。

[`@deepseek-ai/dsh-api-workspace-files`](../../../../packages/api/workspace-files/README.zh.md) 暴露 `workspaceFiles.write`：整文件替换，可带版本守卫，返回新版本、是创建还是更新，以及被替换掉的旧内容。[`@deepseek-ai/dsh-client-ui-sidebar-documentpreview`](../../../../packages/client/ui-sidebar-documentpreview/README.zh.md) 新增 `TextEditor`、文档渲染器定义上的 `editable` 能力，以及其 store 与 face 中的编辑会话。

### 草稿整文件读取，绝不由分页拼装

`openDraft` 通过 `workspaceFiles.readAll` 读取文件，并用 `TextDecoder('utf-8', { ignoreBOM: true })` 解码。整文件读取正是让保存不具破坏性的原因：草稿就是文件本身，因此读者只输入一个字符再保存，写回的就是同样的字节加上那一个字符。`ignoreBOM` 是刻意的——默认解码器会剥掉开头的字节序标记，那会在首次保存时把它删掉。CRLF 换行出于同样的原因得以保留：文本在整条路径上都没有被规范化。

分页读取未被改动。编辑器与预览以两条不同的路径读取同一个文件，预览持有的 `pages` 从不作为草稿的初值。

### 保存由草稿来源的版本守卫

草稿携带整文件读取报告的 `version`，保存时作为 `expectedVersion` 发送。Host 把它重新标记到文件系统的不透明 token 上，并以 `workspace-file/stale-version` 拒绝已被他人推进的文件；不写入任何内容，也不尝试合并。编辑器把该拒绝报告为**冲突**——唯一带有决策的失败——并恰好给出两条出路：**覆盖保存**（省略守卫保存）与**放弃并重新载入**（再次整文件读取并采用另一位写入者的版本）。

只有冲突路径会不带守卫传输。其余每一种拒绝——只读 Session、已结束的 Session、后端失败——都作为普通失败报告，草稿与其基线保持不变，因为原样重试是唯一合理的下一步。

保存不会关闭会话，也不会在完成时回写草稿。在写入进行期间继续输入的读者，其文本比文件更新，因此被接受的写入成为干净的*基线*，更新的击键会让该 tab 正确地重新变为已修改。

### Host 以存活的 Session 与可写策略为写入门禁

`write` 是该服务唯一的变更操作，除读取门禁之外还有两重门禁。Session 必须**存活**——已结束的 Session 没有可解析的策略覆盖，服务宁可失败关闭也不回退到部署默认值。随后解析出的沙箱策略必须允许写入；`read-only` 会拒绝。两项检查都不询问 Client，Agent 自身写入工具所携带的提权词汇在协议上没有对应物，因此浏览器无法为自己请求比其 Session 已有的更大模式。

能力门禁先于路径门禁运行，因此拒绝时不会解析任何路径，该端点也不会被它即将拒绝的调用者当作路径探测器。随后读取门禁原样生效：路径必须存在、是普通文件，并通过服务既有的包含关系与符号链接处理。成功写入会发出与工具写入相同的 `fs/observed` 观察，因此每一个打开的 `changes` 世代都会得知它。

### 编辑能力由渲染器声明，而非由其加载模式推断

`DocumentPreviewDefinition` 新增 `editable`，纯文本、Markdown 与代码渲染器会设置它。它是声明的而不是从 `loading: 'text-pages'` 推导的，因为分页渲染器并不自动等于文本渲染器，只有确知自己的文件是 UTF-8 文本的实现才应提供写回。HTML、图片与 PDF 渲染器加载完整字节，不提供编辑。

### 窄栏只显示一个视图；全屏同时显示两者

面板为窄栏时，编辑器占据整列，预览被**隐藏而非卸载**，因此正文的滚动容器保留读者的位置，返回预览也是即时的。当面板进入全屏，两者以各占一半的固定比例共用该列——没有可拖拽的分隔条，因此任何一侧都不会停留在读者无法恢复的尺寸。预览一侧会通过并排改动对比原本就在使用的那同一个 effect，在编辑器背后继续分页直到文件末尾。

离开编辑器是一个控件，而已修改的草稿会守住它：在读者保存或明确放弃之前，预览切换控件处于禁用状态。未保存标记就在控件旁边。

## Alternatives considered

**以已加载的分页作为草稿初值。** 已拒绝，而这正是整个功能所系于的那个决定：分页文本在文件末尾是有损的，因此首次保存会剥掉读者从未触碰过的末尾换行。在文件"看起来像"有换行时补一个换行，无法从分页数据中恢复，因为分页并不携带这一位信息。

**浏览器端 CodeMirror 6 编辑器。** 已拒绝，并据此修正了提出它的计划。CodeMirror 不是本仓库的依赖，采用它意味着浏览器包中的新包以及 `pnpm-lock.yaml` 的改动；它换来语法着色、行号与括号匹配，而编辑契约并不需要这些，它还会引入需要与 store 保持同步的第二份文档模型。朴素的 `<textarea>` 零依赖即可交付完整契约——一个滚动文本表面，其值由所有者持有，其每一次击键都被所有者听到。升级路径依然廉价：`TextEditor` 是一个位于三属性接口之后的叶子组件，因此更换该表面只涉及一个文件，既不动 store 也不动 face。

**以补丁或单区块编辑代替整文件替换。** 已拒绝：编辑器的工作单元是读者的缓冲区，因此整文件写入正是它实际持有的内容，而 `@deepseek-ai/dsh-fs` 已为确实拥有字面替换的调用者提供了 `editText`。

**让浏览器请求沙箱模式。** 已拒绝：沙箱策略在 Host 上由 Session 解析。能够指定模式的 Client 等于在给自己授予能力，而这正是该 seam 存在所要防止的唯一一件事。

**自动保存。** 已拒绝：预览同时也在观察文件的外部改动，因此自动保存的编辑器会与 Agent 争夺同一个文件，且没有任何时刻是读者选择了某一方。显式保存才让版本守卫有意义、让冲突可被解决。

**可拖拽的分栏分隔条。** 暂不采纳：它是每个 tab 需要持久化与重置入口的布局偏好，而固定各半已满足分栏存在的场景。分栏只是一个元素上的 CSS 属性，因此日后改为可拖拽是增加状态，而不是重构布局。

## Consequences

读者现在可以在他们本来就在阅读的面板中修正 Markdown 文件——或任何文本、代码、纯文本文件——并在旁边的预览中看到结果，而无需离开产品。Agent 的写入与读者的写入由同一个版本 token 排序：后写入的一方会被拒绝并被询问，而不是静默胜出。

代价记录在包的 README 中。编辑仅限整文件，因此超大文件受服务 `maxFileBytes` 上限（默认 32 MiB）以及 `<textarea>` 能舒适容纳的规模约束——对于编辑器不会打开的文件，分页预览仍然可用。没有语法高亮、没有行号、没有多光标。草稿存放在 tab 的 store 中，因此切换 tab 会保留，但重新加载页面不会，关闭 tab 会在不询问的情况下丢弃它。编辑器以 UTF-8 写入：分页读取接受为文本的文件可以逐字节往返，但浏览器无法把其他编码写回。

四个测试套件钉住已交付路径。`packages/api/workspace-files/tests/write.spec.ts` 覆盖 Host 方法：版本守卫、强制覆盖、只读与已结束 Session 的拒绝、门禁顺序、未被改动的读取门禁，以及写入发出的观察。`packages/client/ui-sidebar-documentpreview/tests/text-edit.client.spec.tsx` 覆盖读者经由真实 store 与 face 的路径：进入编辑器、已修改标记、保存携带的守卫、两种冲突解决方式，以及窄栏与全屏布局。`tests/face.client.spec.ts` 覆盖会话的回收规则——在读者离开后才完成的草稿读取或保存不写入任何内容——而 `tests/rpc.client.spec.ts` 钉住整文件解码，包括分页读取本会牺牲的字节序标记与 CRLF 换行。
