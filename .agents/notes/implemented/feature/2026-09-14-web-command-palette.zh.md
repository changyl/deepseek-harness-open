# Agent Note: Web 命令面板

Status: implemented

[English](2026-09-14-web-command-palette.md) | 中文

## Problem

Web GUI 过去只能通过输入框触达命令：输入 `/name`，或打开输入框的 `+` 菜单。两者都要求对话与输入框在视野内，也都不是用户在任何位置都能做出的键盘手势。此外有两个日常操作在其自身控件之外没有任何入口：新建会话只有侧栏按钮，停止正在运行的轮次只有输入框的主按钮在会变成 Stop 的那些状态下提供。

客户端也没有任何东西拥有全局按键。键盘处理散落在输入框 keymap 与各个弹窗里，因此第二个界面想占用一个组合键，就不得不自行添加一个 document 监听器，并自己承担组字状态、已消费事件与顺序规则。

## Decision

新增一个客户端包 `@deepseek-ai/dsh-client-ui-command-palette`，由它拥有键盘层与命令面板；`ctx.commandUi` 增加了无输入框界面所需的那两个方法。命令仍由命令界面拥有，命令面板只是同一批行之上的第二个视图。

### 命令界面增加一次查询与一次裸运行

`CommandUiContract` 增加 `palette(session, signal)` 与 `run(name, session)`。`palette` 是既有的候选合成在行首位置、去掉排序后的结果：即 `/` 菜单在行首展示的行，按[输入框菜单决定](2026-09-08-composer-menu-sections-and-localized-rows.zh.md)所拥有的分区顺序、不含贡献项图标。`run` 是不带输入框 token 的菜单选择——可用的贡献项、其次是对可解析宿主行生效的装饰、最后是以分离方式运行的宿主行裸命令行。两个方法都不重新推导目录、可用性门禁或名称冲突规则：两者都调用输入框已经在用的私有路径。

命令面板的行类型刻意不含贡献项图标。`ComponentType` 既不是 JSON 兼容数据也不是回调，而注入值与渲染状态只接受这两类值，因此 overlay 按条目类型各画一个字形，而输入框菜单保留逐命令的组件渲染。

### 命令面板是这些行之上的视图

`CommandPaletteController` 持有一个快照 store，以及 overlay 的注入面与快捷键绑定都会调用的动词。打开时记录当前会话 id，发布本界面自己拥有的操作——始终有「新会话」，该会话有正在运行的轮次时有「停止生成」——并启动一次加载。输入只在本地对已加载的行重新排序，不再发出查询，因此每次打开只触达一次线路。加载代数计数器加上 `AbortController` 使被取代或已关闭的加载不写入任何内容，这正是快捷键开关与重试按钮能够共用同一个 `open()` 的原因。

行是判别联合（`new-session`、`stop`、`command`），选择按该判别字段派发：通过可选服务调用 `ctx.uiWorkspace.startSession()`、所绑定会话的 `cancel()`，或 `ctx.commandUi.run(name, session)`。命令行携带读取其目录时所针对的会话 id，因此派发无需第二次查找，也不会与已展示的内容发生漂移。

### 一个键盘注册表，而不是每个功能各一个监听器

`ctx.shortcuts` 拥有唯一的 document keydown 监听器，并按注册顺序向已注册绑定派发，首个匹配者胜出，修饰键精确匹配。组合键在注册时解析并校验，因此格式错误的 spec 或重复 id 会在插件加载时失败，而不是等到第一次按键；注册是调用方 fiber 上的 effect，因此插件的组合键会随它一起离开。组字过程中的按键，以及已被其他处理函数消费的事件，都不会被触碰；`mod` 接受平台命令键或 Control，因此同一份 spec 同时服务 macOS 与 Windows/Linux。

命令面板把 `mod+k` 与 `mod+shift+p` 绑定到同一个开关。

### 无输入框的弹窗不消费任何内容

`TokenSegment` 增加了 `palette` 变体。弹窗通过消费打开时快照的段来落实选择，而 menu 或 enter 段会指名要清除的输入框 token（或 span）。命令面板的选择不拥有 token：它的段不消费任何内容，因此命令面板从未拥有的草稿不会被它打开的弹窗清除。`consumeVia` 收窄到携带 token 的段，从而把这一区分留在类型里，而不是放在一个没有任何测试覆盖的运行时检查中。

## Alternatives considered

**把命令面板做在 `ui-commands` 内部。** 命令面板读取同一个目录，因此另起一个包看起来像多余的间接层。否决原因：命令面板是带自己键盘层、自己独立于会话的生命周期以及自己两个操作的全局 overlay；把它并入会让 `ui-commands` 拥有一个与命令来源毫无关系的键盘注册表，而该包的导出纪律也禁止外部触达其内部实现。

**通过 `toggleSource('command', …)` 驱动输入框的斜杠流水线。** 这能返回完全成型的候选列表，包含贡献项与装饰。否决原因：输入框的 `MenuView` 与命令面板会读取同一个按会话的菜单 store，因此打开命令面板也会打开输入框下拉菜单——而且在没有输入框可用的视野里，命令面板将无法使用。

**直接读取 `ctx.remote.commands.list(sessionId)`。** 只需一次 RPC，也无需新契约。否决原因：它有损——会丢掉客户端贡献项与装饰，而它们恰恰是命令面板存在的理由（`/model`、`/permission`、`/file`），同时丢掉它们的可用性门禁、内置的本地化外观，以及 Add/Commands 的分区顺序。

**让每个功能包用自己的监听器绑定自己的组合键。** 无需新服务，每个功能也能把按键留在本地。否决原因：每个监听器都要重新实现组字状态、已消费事件与顺序规则，而且两个功能可能占用同一组合键，却没有定义好的胜出者。

## Consequences

Web GUI 获得了通往当前会话可运行的全部命令的键盘路径，以及在任何位置触达「新会话」与「停止」的能力。`scripts/verify-client-ui-i18n` 通过 `commandPalette` locale 命名空间约束命令面板的文案；该包自身的测试套件钉住组合键解析与匹配、控制器的加载与取代、各渲染状态，以及浏览器半边注册与释放。

三项限制是有意为之，并已记录在包 README 中：行在每次打开时只读取一次，命令行共用一个字形，需要参数的宿主命令以裸形式运行并展示其提示。逐命令图标需要一条不把组件类型放进共享数据的通道；行内容实时刷新需要控制器当前并未持有的订阅。

命令面板仅存在于浏览器。它内部没有任何内容触达模型，也没有任何提示词、工具 schema 或会话事件发生变化，因此没有已录制的会话快照需要变动。
