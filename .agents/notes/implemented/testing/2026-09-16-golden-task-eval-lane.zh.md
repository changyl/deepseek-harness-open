# Agent Note: 用黄金任务度量模型有效性

Status: implemented

[English](2026-09-16-golden-task-eval-lane.md) | 中文

## Problem

harness 此前能证明两件事：改动之后自身代码依然够快（`benchmarks/`，用不含模型的合成输入运行），以及录制过的会话仍然产出同样的转录（`snapshots/`，无密钥回放）。两者都没有回答部署真正会问模型的那个问题：在这个工作区里给出这个任务，它被解决了吗？

转录可以逐字节相同，而任务要求的文件却是错的，因为快照比较的是对话，而不是结果。而且快照没有分数、基线或成本的概念，因此没有任何东西能说明：对提示词、工具描述或模型路由的改动让结果变好了还是变坏了。[effectiveness 投影](../../../../packages/feedback/effectiveness/README.zh.md)覆盖的是会话自身信号对它的说法；它无法判断工作是否正确。

## Decision

顶层 `evals/` 目录负责黄金任务评测，根脚本把它暴露为 `pnpm run test:eval` 与 `pnpm run test:eval:update-baseline`。

一个用例就是 `evals/cases/` 下的一个目录：`task.md` 是提示词，`eval.yml` 携带 profile、轮次与时间上限以及断言，`workspace/` 是原始夹具。runner 把夹具复制到每个用例各自的临时新目录，把该目录交给注入的执行器，并针对这次运行留下的结果评估断言：文件是否存在、文件内容、文件缺失、与夹具字节的哈希比较，以及某条命令的退出码与固定 stdout。任何断言都不解析模型的叙述，因此用例不会因为模型说它成功了而通过。

执行器是已发布的 headless profile：该 lane 用私有的 `DSH_HOME` 启动 CLI，因此这次运行既看不到也不会破坏开发者自己的会话，随后从它自己的持久日志——`turn/end` 计数与 provider 上报的 token 桶——而不是从 stdout 度量这次运行。当部署保留了 `evals/rates.json` 时，该 lane 通过 usage 能力缝自身的 `routeCostMicros` 为这些桶计价，因此成本数字与产品使用的是同一套算术。

`evals/baseline.json` 记录上一次被接受的逐用例状态，外加每个金任务的一份摘要：提示词、运行上界、夹具清单与断言。当某个记录为 `passed` 的用例现在失败时，该 lane 失败；对于基线不知道的用例以及本次运行未覆盖的基线用例，它会报告出来但不因此失败，因为一个失败的用例完全可能开始通过。摘要是该 lane 在没有密钥时仍然强制的内容——被改动的任务、断言集或夹具清单都会让它变红——因此 `--update-baseline` 会记录摘要，而已记录的状态在模型运行能够替换它们之前保持不变。

该 lane 会调用真实模型，因此在缺少 `DEEPSEEK_API_KEY` 时会给出明确的说明并以退出码 0 自跳过，与 e2e lane 完全一致。无密钥环境下的绿色运行意味着"未被度量"，绝不是"通过"。

## Alternatives considered

**给 `benchmarks/` 加上正确性用例。** 那棵目录树的存在是为了捕获性能回归：固定的合成输入、不含模型、不联网，以及环境变量不得覆盖的预算。模型调用既不确定，也不是预算形状的，把它放进去会让每个性能门禁都依赖某个 provider。两棵树，两个问题。

**复用 session-snapshot lane。** 快照钉住的是转录，其夹具是无密钥回放的录制会话，这正是它们廉价且确定的原因。除了一次显式的 workspace 比较之外，它们对运行产出的文件不作任何断言，也没有分数或基线概念。该 lane 保留了可迁移的部分——在全新工作区里运行已发布的 profile——并加上断言与分数。

**把该 lane 做成包而不是一棵目录树。** 一个包会加入发布族、workspace 约束与逐文件覆盖率门禁，而这些都不适合一个会启动 CLI 的工具。目录树在维持同一测试标准的同时，不必假装该 lane 是产品面。

**在进程内而不是子进程里执行任务。** 进程内运行会继承 harness 自己的工作目录、环境与已加载的组合，因此用例可能因为开发者自己的会话恰好配置正确而通过。带私有 home 与复制工作区的子进程，才是用例的输入恰好等于该用例输入的唯一样子。

**给转录打分而不是给工作区打分。** 让第二个模型来评判这次运行，会给一个本就为跨运行可比而存在的度量再加一个不确定步骤，而且会让分数取决于评判者的路由。文件、退出码与 stdout 虽然乏味，但可比。

## Consequences

模型有效性现在有了归属、分数与回归门禁：通过率、每个已解决用例的 token 数、每个已解决用例的成本，全部来自这次运行自身产出的证据。提示词或工具描述的改动，可以通过改动前后运行同一批用例来评估。

该 lane 的诚实性取决于它的用例与一把密钥。无密钥运行只能证明该 lane 接线正确。三个用例度量的是三项狭窄能力，而不是一个模型。成本数字只在部署保留费率表时出现，token 数字则是 provider 对上报了 usage 的那些步骤的上报值。该 lane 还会消耗真实 token，因此它是 owner 运行的 lane，而不是逐 PR 的门禁，直到某个部署另有决定。

## Testing

该 lane 自身的逻辑在无模型的情况下被覆盖：用例加载及其各类拒绝、每一种断言（包括路径逃逸拒绝与固定 stdout 校验）、套件的工作区隔离与字节不变语义、执行器崩溃路径、打分与基线比较、报告，以及带计价的会话日志折叠。无密钥路径通过在不带密钥的情况下运行 `pnpm run test:eval` 来验证：它会比对任务摘要，把漂移报告为失败，否则报告跳过并以 0 退出。
