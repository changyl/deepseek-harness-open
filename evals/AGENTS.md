# AGENTS.md — Golden-task evaluation lane

This tree measures whether a model solves a whole task through the shipped profile: it runs each case in a fresh workspace, asserts the workspace the run left behind, and compares the result with a checked-in baseline. It answers a different question from `benchmarks/`, which measures the harness's own performance on synthetic inputs — never add timing budgets or performance assertions here, and never add model runs there.

- One case is one directory under `cases/`: `task.md` is the prompt, `eval.yml` is the run configuration and the assertion list, and `workspace/` is the pristine fixture copied into the run. A case with no `workspace/` starts from an empty directory.
- Assertions are deterministic and independent of the model's report. The workspace, the exit codes, and the pinned stdout decide the case; nothing parses the model's prose.
- `unchanged` means the file still hashes to its fixture bytes, and a path the fixture did not hold must stay absent. Use it on every file the task must not touch — a test the model is told not to edit, a configuration it must read.
- A fixture must be runnable with the toolchain the case assumes and nothing else. Prefer plain `node` over project tooling: the run's workspace is a copy, not a checkout, so a case may not depend on `node_modules`, a package manager, or the network.
- Keep every case small enough to fail for one reason. A case that needs several unrelated edits to pass cannot say which capability regressed.
- The lane's logic belongs in `support/`, and every module there stays testable without a model: the executor is injected, assertions read a directory, and scoring reads outcomes.
- `baseline.json` records the last accepted per-case status plus one digest per golden task. Run `pnpm run test:eval:update-baseline` only when a reviewed change explains the new result, and keep the diff in the same PR. A case recorded as `passed` that now fails makes the lane exit non-zero; a case that was already failing may flip either way without failing the lane. Without a key that command still records the digests and leaves the recorded statuses alone.
- The lane calls a real model, so the model half of `pnpm run test:eval` self-skips without `DEEPSEEK_API_KEY`. The task digests do not: the lane still loads every case and fails when a task prompt, its bounds, its fixture inventory, or its assertions differ from `baseline.json`, so a golden task cannot rot unnoticed while no key is present. It reports the skip rather than pretending to have measured anything; CI owns the recorded evidence and the platform matrix.
- Never commit a session log, transcript, or recorded fixture from an eval run. The lane keeps its evidence in the temp workspace and the printed table, and the durable record is the baseline.
- Report figures the run produced: `turn/end` count and provider-reported tokens come from the session log the run wrote under its own `DSH_HOME`, priced by `rates.json` when the deployment keeps one.
